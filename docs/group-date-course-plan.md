# 그룹 취향 기반 데이트 코스 생성 계획

## 목표

사용자가 그룹을 만들고 참여 멤버를 선택하면, 각 멤버의 공개된 취향과 그룹에 저장한 장소를 바탕으로 모두가 납득할 수 있는 데이트 코스를 생성한다.

기존 개인 추천 에이전트는 그대로 유지한다. 그룹 기능은 `features/group-date-course` 안에서 그룹 데이터를 개인 추천 요청 형식으로 변환하고, 기존 Bedrock 호출·일정 계산·검증 로직을 재사용한다.

## 설계 원칙

- 그룹 멤버만 그룹 데이터와 추천 결과에 접근할 수 있다.
- `profile_visible_in_groups=false`인 멤버의 개인 저장 장소와 취향은 그룹 추천에 사용하지 않는다.
- 원본 릴스 자막과 개인 저장 목록은 추천 응답에 노출하지 않는다.
- 식단·접근성 같은 하드 제약은 취향 점수보다 우선한다.
- 단순 평균으로 상반된 취향을 지우지 않는다.
- LLM은 장소 선택·순서·설명을 맡고, 시간·이동·예산·영업시간 검증은 코드가 맡는다.

## 폴더 구조

```text
features/group-date-course/
├── types.ts
├── schema.ts
├── member-profile.ts
├── aggregate-preferences.ts
├── rank-for-group.ts
├── fairness.ts
├── load-group-context.ts
├── agent.ts
└── repository.ts
```

Next.js 진입점과 데이터베이스 변경은 프레임워크 규칙에 맞춰 다음 위치에 둔다.

```text
app/api/groups/[group_id]/itineraries/route.ts
supabase/migrations/*_group_itineraries.sql
```

그룹 화면(`app/(app)/groups/**`)은 이 계획에 포함하지 않는다. 재사용 가능한 초대
스키마(20260920000010) 위에서 이미 다시 만들어졌고, 이 모듈은 그 화면이 호출할 수
있는 API 하나만 제공한다.

## 추천 흐름

1. 요청자가 그룹 멤버인지 확인한다.
2. 선택한 참여자가 모두 해당 그룹 멤버인지 검증한다.
3. 참여자별 MBTI, 공개 설정, 저장 장소 카테고리와 지역을 불러온다.
4. 참여자별 취향 벡터를 정규화한다.
5. 그룹 공유 장소와 공개 프로필의 개인 저장 장소를 우선 후보로 만든다.
6. 후보가 부족하면 같은 지역의 장소 DB에서 보충한다.
7. 후보마다 멤버별 만족도와 그룹 점수를 계산한다.
8. 그룹 취향을 기존 `CourseRequest`로 변환해 Bedrock 추천 에이전트를 실행한다.
9. 기존 코드로 시간표, 이동 시간, 예산, 영업시간을 검증한다.
10. 각 멤버에게 최소 한 곳 이상의 취향 적합 장소가 있는지 검사한다.
11. 소외된 멤버가 있으면 해당 멤버의 상위 후보를 고정하고 한 번 재생성한다.
12. 요청, 취향 스냅샷, 결과와 공정성 점수를 저장한다.

## 그룹 점수

후보 장소의 그룹 점수는 다음과 같이 계산한다.

```text
그룹 점수 = 평균 만족도 55% + 최저 만족도 30% + 멤버 커버리지 15%
```

- 카테고리 일치도를 기본 신호로 사용한다.
- 자주 저장한 지역과 일치하면 보너스를 준다.
- 취향 데이터가 없는 멤버는 점수를 왜곡하지 않도록 중립값을 사용한다.
- 결과 코스에서 데이터가 있는 각 멤버가 최소 한 정류장에서 기준 점수 이상을 받아야 한다.

## MBTI 정책

- MBTI를 모르는 멤버도 그룹 추천에 참여할 수 있다.
- 참여자들의 네 MBTI 축을 다수결로 조합한 대표 유형을 코스 구성과 설명 톤에만 사용한다.
- 동률인 축은 요청자의 값을 사용하고, 요청자도 값이 없으면 중립 기본값을 사용한다.
- 장소 적합도는 저장 행동 기반 취향이 MBTI보다 우선한다.

## API

`POST /api/groups/{group_id}/itineraries`

```json
{
  "member_ids": ["uuid-1", "uuid-2"],
  "date": "2026-10-03",
  "time_range": "14:00-19:00",
  "region": "성수",
  "start_station": "성수역",
  "budget_per_person": 50000,
  "hard_constraints": {
    "no_spicy": true,
    "limited_walking": false,
    "allow_taxi": false
  },
  "pinned_place_ids": []
}
```

응답은 추천 결과와 그룹 적합도 정보를 함께 반환한다.

```json
{
  "id": "itinerary-uuid",
  "course": {},
  "group_match": {
    "member_coverage": [],
    "stop_attributions": [],
    "fairness_score": 0.84
  },
  "created_at": "2026-10-03T05:00:00.000Z"
}
```

## 저장 모델

`group_itineraries`에는 다음만 저장한다.

- 그룹과 요청자
- 참여자 ID 목록
- 사용자가 입력한 제약 조건
- 추천 당시 정규화된 취향 스냅샷
- 최종 추천 결과와 공정성 점수
- 생성 상태와 생성 시각

원본 자막과 개인 저장 목록은 복제하지 않는다.

## 화면

1. 그룹 목록에서 새 그룹을 만든다.
2. 그룹 상세에서 멤버와 공유 장소 수를 확인한다.
3. 코스 참여 멤버를 선택한다.
4. 날짜, 시간, 지역, 출발역, 예산을 입력한다.
5. 생성된 코스에서 정류장별 멤버 적합 근거를 확인한다.

초기 버전에서는 실시간 공동 편집과 채팅형 수정을 제외한다.

## 완료 기준

- 그룹 외 사용자의 접근이 차단된다.
- 그룹에 없는 사용자 ID를 참여자로 선택할 수 없다.
- 후보군 밖 장소를 생성하지 않는다.
- 하드 제약, 영업시간, 예산, 이동 시간 검증을 통과한다.
- 취향 데이터가 있는 모든 참여자가 최소 한 정류장에서 반영된다.
- 비공개 프로필의 개인 데이터가 입력과 응답에서 제외된다.
- 기존 개인 추천 테스트가 그대로 통과한다.
- 그룹 취향 집계와 공정성 검증 단위 테스트가 통과한다.

그룹 추천 자체 검증은 다음 명령으로 실행한다.

```bash
npx tsx scripts/group-date-course.self-check.ts
```
