# 추천 AI 에이전트 설계 전 결정사항

- 문서 상태: 사용자 검토용
- 작성일: 2026-09-20
- 기준 문서: [MBTI 시스템 프롬프트 설계서](./mbti-date-course-prompt-plan.md)
- 관련 설정: [MBTI 코스 프로필](../packages/shared/mbti-course-profile.json)
- 관련 프롬프트: [데이트 코스 시스템 프롬프트](../packages/shared/prompts/date-course-system.md)
- 출력 계약: [코스 응답 JSON 스키마](../packages/shared/course-response.schema.json)

이 문서는 추천 AI 에이전트를 구현하기 전에 제품 정책과 기술 경계를 확정하기 위한 체크리스트다.
각 항목의 선택 또는 직접 입력 부분을 채우면 다음 단계에서 에이전트의 입력 계약, 도구,
점수 계산, 프롬프트, 검증 로직을 확정할 수 있다.

## 4. MBTI 캐릭터 정책



### 4.1 MBTI 입력 방식

- [x] 사용자가 자신의 MBTI를 직접 고른다. **(권장)**
- [ ] 간단한 질문으로 추천 캐릭터를 고른다.
- [ ] 저장 영상으로 MBTI를 추측한다.

저장 영상으로 실제 MBTI를 추측하는 방식은 정확도와 고정관념 문제가 있으므로 사용하지 않는 것을 권장한다.

### 4.2 사용자의 직접 조정

MBTI 기본값보다 사용자의 명시적 선택을 우선할지 결정한다.

- [ ] 조용함 ↔ 활기참
- [ ] 검증된 장소 ↔ 이색 장소
- [ ] 효율적 설명 ↔ 감성적 설명
- [ ] 즉흥적 일정 ↔ 계획적 일정

- [ ] 위 4개 슬라이더를 노출한다.
- [x] MBTI만 선택하고 슬라이더는 숨긴다. **(MVP 권장)**
- [ ] 추천 결과에서 한 번에 한 축만 조정하게 한다.



### 4.3 캐릭터 문구

현재 16개 MBTI 유형에 캐릭터명과 한 줄 콘셉트가 정의되어 있다.

확인할 것:

- [x] 캐릭터명이 서비스 톤과 맞는다.
- [ ] 특정 유형을 부정적으로 보이게 하는 이름이 없다.
- [ ] MBTI가 사용자의 성격이나 연애 방식을 단정하지 않는다.
- [ ] 캐릭터별 결과 차이가 장소보다 코스 구성과 설명에서 자연스럽게 보인다.

수정이 필요한 유형:

> 유형 / 새 캐릭터명 / 새 한 줄 콘셉트:

- 사용자가 고정한 장소는 pinned로 표시한다.
